three things this design buys

Numbers cannot drift same service
Key never reaches the browser backend only
Empty answer is a failure never stored

The last one matters more than it looks. The model bills its reasoning against the token budget, so a stingy limit returns a success status carrying no answer at all. That empty response is treated as an honest failure rather than saved as advice.

three roles, one system

Permission is not a role check. It is an assignment check.

Most systems ask whether someone is a teacher. This one asks whether they teach this exact subject, in this section, this semester, this academic year.

Student

  • Attendance, marks, GPA and trends
  • AI assistant and study plans
  • Coding playground and contests
  • Drives, applications and resumes
  • Interview prep and scheduling
Reading another student's record returns 404, not 403, so an id cannot be probed for existence.

Faculty

  • Only the classes they are assigned
  • Roster marking and bulk marks entry
  • Exam scheduling
  • Cohort analytics for those classes
  • Announcements to their own department
Acting on an unassigned subject is 403 at the service layer, not just at the route.

Administrator

  • Provisioning and student activation
  • Departments, courses, subjects
  • Grade bands and performance thresholds
  • Companies, drives and shortlisting
  • Institution-wide analytics
Self-registration only ever creates a pending student. Staff accounts come from an existing admin.
what does not work

The part most products leave out.

A system that names its own limits is easier to believe than one that claims none. These are current and accurate.

Code execution
The sandbox needs cgroup v1 and the development machine's container runtime provides only v2, so no submission can actually run. Everything around execution works: the editor, hidden test cases, submission history, contests and both leaderboards. A submission records INTERNAL_ERROR with the real connection message rather than inventing a verdict, and the database will not store an accepted result that was not earned.
File uploads
There are none anywhere in the system. The only file-shaped feature is a server-generated resume PDF going out. Recorded as a scope gap rather than ticked off a checklist.
Dropdown labels
A defect found while checking the interface in a real browser: every select displays its raw value instead of the chosen option's label. One shared component causes it, and it is queued for the next pass rather than quietly left.
